🔄 Arsitektur Aliran Data (Data Flow): Vue → Laravel → Basis Data
Soal 6.b & Soal 8
🖥️
Frontend (Vue 3)
SPA Single Page Application disajikan oleh Nginx Alpine
Container: uts-frontend:3000
→ HTTP / JSON
⚡
Backend (Laravel 11)
FrankenPHP Caddy Server melayani RESTful API & Auth Sanctum
Container: uts-backend:8000
→ TCP 3306
🗄️
Basis Data (MariaDB)
Relational DB menyimpan tabel users, produks, personal_access_tokens
Container: uts-db:3306
→ Mount
💾
Named Volume
Persistensi data fisik di Docker Host agar tidak hilang saat restart
Volume: uts_db_data

Penjelasan Langkah Aliran Data (End-to-End Data Flow):

1
Interaksi User di Browser: Pengguna membuka katalog di http://localhost:3000, mengisi form "Tambah Produk Baru", lalu menekan tombol Simpan. Event handler memicu fungsi createProduk().
2
Axios Interceptor & HTTP Request: Axios mengambil token Sanctum dari localStorage dan menyematkan header Authorization: Bearer <token>, lalu mengirimkan request POST /api/produks dengan payload JSON ke backend.
3
FrankenPHP & Laravel Processing: Server FrankenPHP menerima request pada port 8000, middleware Sanctum memvalidasi token, dan ProdukController::store() melakukan validasi input (nama, harga, stok, dsb.).
4
Kueri Eloquent ke Basis Data: Laravel Eloquent ORM mengeksekusi kueri INSERT INTO produks (...) ke host db:3306 melalui jaringan Docker Compose internal (bridge network uts-network).
5
Persistensi Fisik & Respon JSON: MariaDB menulis data ke named volume uts_db_data. Laravel mengembalikan respon 201 Created berisi data JSON produk baru. Vue menerima respon dan langsung me-refresh tabel katalog secara reaktif.
